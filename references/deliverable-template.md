# 交付物模板

默认交付**两份文件**：一份结构化 Markdown（人读），一份纯文本（机器读 / 复制用）。

## 主文档结构

文件命名：`<主题简称>_视频文字稿.md`，与内容主题相关，不要用「转写结果」这类无信息量的名字。

```markdown
# <视频标题原文>

| 项目 | 信息 |
| --- | --- |
| 视频标题 | <原文标题，不改写> |
| 作者 / UP主 | <名称> |
| 时长 | <mm 分 ss 秒（总秒数）> |
| 发布 | <YYYY-MM-DD> |
| 播放 / 互动 | <若数据可得，否则删掉此行> |
| 视频地址 | <原始链接> |

> 说明：<字幕直取 / 语音转写>，<是否人工校对>。已校正：A→B、C→D。疑似待核：X。

---

## 一、核心摘要

1. <一条一个事实，不写「讲了版权知识」这种空话>
2. ...
（5~10 条，按信息权重排序，不按时间顺序）

---

## 二、分段结构与时间轴

| 时间 | 内容 |
| --- | --- |
| 00:00 | <该段落干了什么> |
| ... | ... |

（8~30 行；少于 5 分钟的视频可省略本节）

---

## 三、完整文字稿（带时间戳）

**[00:00]** <正文>

**[00:21]** <正文>

---

## 四、关键概念 / 待办 / 引用（可选）

（术语表、延伸问题、原文提到的清单——按内容性质选一个，不要硬凑）
```

## 纯文本版

`<同名>_纯文本.txt`，规则：

- 去掉全部 `**[时间戳]**` 与 Markdown 标记
- 段间空一行，保持可读性
- 顶部保留三行元信息（标题 / 作者时长 / 链接）与来源说明
- 不写摘要，只放正文

## 变体

| 用户要的 | 调整 |
| --- | --- |
| 只要文字，别搞花活 | 只给纯文本 + 一行元信息，不做摘要和时间轴 |
| 要做学习笔记 / 讲解材料 | 摘要扩成 10~15 条，时间轴升级为「章节 + 要点」，正文可折叠为附录 |
| 要做字幕文件 | 交付 `.srt`（`bili_fetch.py` 已能直出），并附一句「未逐句校对」 |
| 要喂给别的模型 | 只给 `_plain.txt`，并告知字符数 |
| 内容敏感（涉及纠纷、指控） | 摘要只陈述「谁说了什么」，不做评价，专名一律按「只标注」档处理 |

## 反例（别这样写）

- 摘要写成「视频介绍了音乐版权相关知识，分为几个部分」——零信息
- 时间轴每行都是「继续讲解」——没有导航价值
- 全文被润色成书面语，口语特征全无——读者无法判断哪句是原话
- 不注明来源，让人以为逐字核对过
